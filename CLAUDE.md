## Concept
Bento-grid site styled as a "QA engineer's desktop": each tile is a small app widget.
Every line of code, copy, icon and image is original (no Apple icons, no copied text).

## Stack and conventions
- Astro 7 static output, TypeScript strict, plain CSS with tokens in `src/styles/tokens.css`.
- One vanilla TS file per widget in `src/scripts/`; no UI framework.
- Tiles use `src/components/Tile.astro` (sizes 1x1, 2x1, 2x2; `tone="dark"`; `flush` for edge-to-edge media).
- Astro scoped styles do not reach the Tile root element from a tile file: use `Tile` props
  (`flush`, `tone`) or `:global(.your-class)`. Elements created in JS need `:global(...)` styles.
- Grid: 4 columns >= 1024px, 2 columns >= 700px, 1 column below.
- WCAG 2.2 AA, full keyboard support, honour prefers-reduced-motion.
- Every feature ships with a Playwright test. `npm test` must stay green; `npm run check` must be clean.
- Work one phase at a time (see README roadmap). Ask before adding dependencies.

## Live data (Phase 6)
- `functions/api/*.ts` are thin Cloudflare Pages Functions; logic lives in `server/` with an injectable fetch.
- Every live widget must render a sensible fallback when `/api/*` is missing (local preview has no functions).
- `/api/activity` runs each Cloudflare query separately; a failing one lands in its `errors` map and only that card shows "–".
- `npm run build` also writes `dist/activity/build.json` (commit, homepage weight, git stats) via `scripts/build-info.mjs`.
- `src/data/qa-report.json` is generated by `scripts/qa-report.mjs`; never hand-edit numbers in it.

## SEO (Phase 7)
- The site address is `SITE` in `astro.config.mjs`; keep `public/robots.txt` in sync (a test checks).
- Every page needs a share image: `npm run build && npm run og` writes `public/og/<slug>.png`.
- Lighthouse budgets live in `scripts/qa-report.mjs`; don't lower them to make CI pass, fix the page.

## Design (v2)
